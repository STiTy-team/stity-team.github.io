# 이름 규칙과 버전

설정 이름만 보고 무엇인지 알 수 있어야 해요. 그래서 이름에는 비교할 때 갈리는
것만 넣고, 나머지는 파일 안에 둬요. 그리고 **한 번 실행에 쓴 이름은 뜻이 바뀌면
안 돼요.** 내용을 바꾸려면 버전을 올려요. <!-- S03-C001-01 S01-C001-15 -->

## 이름의 모양

| 종류       | 칸 (이 순서로)                  | 예                                                        |
| ---------- | ------------------------------- | --------------------------------------------------------- |
| 데이터셋   | `코퍼스_방향[_조건][_부분]`     | `fleurs_ko-en`, `fleurs_ko-en_cafe`, `fleurs_en-ko_top50` |
| 파이프라인 | `역할.모델[+역할.모델…][_변형]` | `asr.qwen-seg-ko+mt.qwen3.5-4b`, `mock`                   |

<!-- S03-C001-02 -->

`[ ]` 안의 칸은 필요할 때만 붙여요. 예를 들어 `fleurs_ko-en_cafe`는 FLEURS
코퍼스, 한국어→영어, 카페 소음이에요. <!-- S03-C001-02 S03-C001-05 -->

## 기호마다 하는 일

| 기호    | 뜻                                                                        |
| ------- | ------------------------------------------------------------------------- |
| `_`     | 칸을 나눠요                                                               |
| `+`     | 한 칸 안에서 여러 개를 이어요 (파이프라인의 부품들, 섞인 언어들)          |
| `-` `.` | 값 안에서만 써요 (`ko-en`, `qwen3.5-4b`, `asr.`)                          |
| `@v<N>` | 버전이에요. 파일 이름에는 쓰지 않아요. `meta.version`에서 자동으로 붙어요 |

<!-- S03-C001-03 -->

- 칸을 나누는 `_` 말고는 소문자, 숫자, `.` `+` `-`만 써요. bench가 시작할 때
  검사해요.
- 언어는 두 글자 코드로 써요 (`ko`, `en`).
- 기본값은 칸을 두지 않아요. 깨끗한 녹음이면 조건 칸이 없고, 전부 돌리면 부분
  칸이 없어요.
- 부품 이름은 코드에 등록된 이름 그대로 써요 (`qwen-seg`, `qwen3.5`). 그래야
  검색돼요.

<!-- S03-C001-04 -->

## 칸에 쓰는 말

새 말을 만들기 전에 아래 말을 먼저 써요. 새로 만들면 `STiTy/configs/README.md`
표에 한 줄 더해요. <!-- S03-C001-05 -->

| 칸   | 말           | 뜻                                        |
| ---- | ------------ | ----------------------------------------- |
| 조건 | `cafe`       | 카페 소음                                 |
| 조건 | `hall`       | 공연장 울림                               |
| 조건 | `lvl26`      | 말마다 −26 dBFS로 소리 크기를 맞춘 데이터 |
| 부분 | `top<N>`     | 가장 긴 N개 (`limit: N`, `pick: longest`) |
| 부분 | `first<N>`   | 앞의 N개 (`limit: N`)                     |
| 역할 | `asr.` `mt.` | 음성 인식, 번역                           |

<!-- S03-C001-05 -->

## meta 블록 {#meta}

`meta`는 설정을 설명만 하고 실행 내용은 바꾸지 않아요. 모든 키를 생략해도 돼요.

<!-- S03-C001-06 -->

```yaml
meta:
  version: 2 # 기본 1. 1이면 이름에 붙지 않아요
  description:
    FLEURS Korean sentences with cafe noise; quiet clips raised to -23 dB
  tags: [fleurs, sentence, noise]
dataset: ...
```

- `description`에는 이름에 없는 것을 적어요. 소음 세기, 어떤 모델 파일인지 같은
  것이에요.
- `tags`는 실험 매니저에서 실행 옆에 나와요. 여러 설정을 가로지르는 묶음에 써요.
  논문에 쓰는 실행이면 `paper`처럼요.
- `description`과 `tags`는 나중에 고쳐도 돼요. 버전을 올릴 필요가 없어요.

<!-- S03-C001-06 -->

## 버전 — 이름의 뜻은 바뀌지 않아요 {#version}

bench는 실행할 때마다 두 설정의 내용(`meta` 제외)과 데이터셋 목록 파일의
지문(해시)을 남겨요. 같은 이름, 같은 버전으로 전에 돈 실행과 하나라도 다르면
**시작하기 전에 멈춰요.** 이 검사는 S3를 통해 모든 머신에서 함께 해요.

<!-- S03-C001-07 S01-C001-34 -->

멈췄다면 둘 중 하나를 해요. <!-- S03-C001-07 -->

1. **뜻이 바뀐 게 맞다면** `meta.version`을 올려요. 실행은 `<이름>@v2`로 따로
   쌓이고 지난 버전의 결과는 그대로 남아요.
2. **실수로 바뀌었다면** 파일이나 데이터를 되돌려요.

::: tip 버전과 새 이름 중 무엇을 고르나요 비교하려는 조건 자체가 새것이면 새
이름을 지어요. 소음 종류나 부분 집합이 그래요. 같은 조건을 고쳐서 다시 재는
것이면 버전을 올려요. :::
