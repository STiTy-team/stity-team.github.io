# 결과 읽기

실행 하나는 폴더 하나예요. 위치는 `bench/runs/<데이터셋>/<파이프라인>/`이고 날짜가 붙지 않아요. 같은 조합을 다시 돌리면 그 폴더를 **덮어써요.** 그 조합의 지금 답이 하나만 남는다는 뜻이에요.

보통은 [실험 매니저](../bench-manager/)에서 보지만, 파일을 직접 열 때 이 문서를 봐요. <!-- S01-C001-26 -->

## 폴더 안의 파일

```
bench/runs/fleurs_en-ko/asr.qwen-seg-en+mt.qwen3.5-4b/
  summary.json          실행 전체의 요약과 점수
  items.jsonl           항목(녹음)마다 한 줄
  events.jsonl          모든 이벤트. Replay가 이 파일을 읽어요
  comet_inputs.jsonl    COMET이 채점할 문장 쌍
  comet_scores.jsonl    문장마다의 COMET 점수
```

<!-- S01-C001-26 -->

- 설정의 `meta.version`이 2 이상이면 이름 뒤에 `@v2`처럼 붙어요. 예: `bench/runs/fleurs_ko-en@v2/mock/`
- 지우려면 그 폴더만 지우면 돼요.
- `.jsonl`은 한 줄에 JSON 하나씩 적은 파일이에요. 실행이 중간에 죽어도 거기까지는 남고 채점돼요.

<!-- S01-C001-26 S01-C001-27 -->

## summary.json에서 볼 곳

| 키 | 내용 |
|---|---|
| `config` | 실행에 쓴 두 설정 파일의 내용 그대로 |
| `components` | 설정에 적지 않은 기본값까지, **실제로 쓴 값** 전부. 두 실행을 비교할 때는 여기를 봐요 |
| `identity` | 두 설정의 이름, 버전, 지문(해시) |
| `source.commit` | 실행에 쓴 코드의 커밋 |
| `counts.realtime_factor` | 처리 시간 ÷ 녹음 길이. 1보다 작으면 실시간보다 빨라요 |
| `counts.empty_transcription_output` | 아무것도 받아쓰지 못한 항목 수 |
| `diagnostics.unavailable` | 낼 수 없었던 점수와 그 이유 |

<!-- S01-C001-26 S01-C001-27 S01-C001-30 S01-C001-33 -->

## 점수의 뜻

| 점수 | 좋은 방향 | 뜻 |
|---|---|---|
| `wer` | ↓ | 틀린 단어 비율. 채점 전에 숫자, 대소문자, 문장부호를 맞춰요. 아무것도 못 받아쓴 항목은 전부 틀린 것으로 쳐요 |
| `wer_by_lang` | ↓ | 언어별 `wer`. `wer`은 이 값들의 평균이에요 |
| `cer` | ↓ | 틀린 글자 비율. 띄어쓰기는 지우고 세요. 한국어 띄어쓰기는 정답마다 달라서예요 |
| `fsl` | ↓ | 오디오가 들어온 뒤 커밋이 나오기까지 늦은 시간(초) |
| `laal`, `laal_ca_ms` | ↓ | 번역이 말보다 평균 얼마나 늦었는지. `_ca`가 붙은 것은 번역이 끝나 전달된 실제 시각 기준이에요 |
| `yaal_ms` | ↓ | LAAL과 비슷하지만 말이 끝나기 전에 나온 번역만 세요 |
| `longyaal_ms` | ↓ | `longform` 실행에서만 나와요. 발표 단위의 번역 지연이에요 |
| `bleu` | ↑ | 번역이 정답 번역과 겹치는 정도. 언어 쌍마다 따로 매기고 평균을 내요 |
| `comet` | ↑ | 모델이 매긴 번역 품질. 빈 번역은 0점으로 쳐요 |
| `token_emission_ms` | ↓ | 단어를 말한 끝 시각부터 그 단어가 화면에 바뀌지 않고 처음 나타날 때까지 |
| `commit_reasons` | | 커밋 이유별 비율. `finish`가 크면 정해 둔 커밋 방식이 제대로 안 도는 거예요 |
| `lang_detect_accuracy` | ↑ | 받아쓴 문장의 언어를 맞게 알아본 비율 |

<!-- S01-C001-28 -->

## 점수가 비어 있다면

bench는 낼 수 있는 점수를 매번 전부 계산해요. 고르는 설정은 없어요. 데이터가 받쳐 주지 못하는 점수는 실패하지 않고 그냥 빠져요. 빠진 이유는 `diagnostics.unavailable`에 적혀요. <!-- S01-C001-30 -->

| 데이터에 있는 것 | 나오는 점수 | 빠지는 점수 |
|---|---|---|
| 녹음만 | `fsl`, `commit_reasons`, `lang_detect_accuracy` | 나머지 전부 |
| 녹음 + 정답 받아쓰기 | 위 + `wer`, `cer`, `token_emission` | `bleu`, `comet`, `laal`, `yaal` |
| 녹음 + 정답 받아쓰기 + 정답 번역 | 전부 | 없음 |

<!-- S01-C001-30 -->

COMET은 따로 된 단계에서 매겨요. 그 단계가 실패하면 `comet`이 `unavailable`에 이유와 함께 남아요. 다시 매기는 법은 [이 컴퓨터에서 돌리기](./run-locally#rescore-comet)에 있어요. <!-- S01-C001-29 -->

## events.jsonl 한 줄 읽기

```json
{"t": 2.0015, "type": "timing", "tag": "flush", "audio": 2.0, "dur": 0.3531}
```

| 키 | 뜻 |
|---|---|
| `t` | 그 항목의 시계를 켠 뒤 흐른 실제 시간(초) |
| `audio` | 그 순간까지 흘려 넣은 녹음의 위치(초). `t`와의 차이가 "녹음보다 얼마나 밀렸나"예요 |
| `type` | 이벤트 종류. `partial`, `transcribed`, `translated`, `timing`, `log` 등 |
| `dur` | 시간이 걸린 일이면 걸린 시간(초) |

<!-- S01-C001-27 -->

`log` 줄에는 프로그램 로그가 섞여요. 번역이 0건인 항목은 여기서 `[DROP]`을 찾아요. 받아쓴 것을 버린 규칙 이름이 붙어 있어요. <!-- S01-C001-27 -->
