# 원격 서버에서 쓰기

GPU 서버에서 도구를 띄우고 내 노트북 브라우저로 볼 때는 두 가지만 알면 돼요.
**SSH 터널**로 웹사이트 포트를 내 컴퓨터로 가져오고, **tmux** 안에서 실행해
접속이 끊겨도 계속 돌게 해요. <!-- S01-C001-09 S02-C001-10 -->

## SSH로 접속하기

```bash
ssh <사용자>@<서버 주소>
```

접속하면 그 창에서 치는 명령은 모두 서버에서 돌아요.

## 실험 매니저를 내 브라우저로 보기

실험 매니저는 서버의 `29140` 포트에서 열려요. 이 포트 하나만 내 컴퓨터로 넘겨
오면 돼요. API 서버(`29130`)는 웹사이트가 안에서 대신 불러서 넘길 필요가 없어요.

<!-- S01-C001-09 S13-C001-01 -->

**내 컴퓨터**의 새 터미널에서:

```bash
ssh -L 29140:localhost:29140 <사용자>@<서버 주소>
```

이 창을 열어 둔 채로 브라우저에서 `http://localhost:29140`을 열어요.

::: tip 녹음 기능도 이 방법으로 열어요 브라우저는 `localhost`나 `https`
주소에서만 마이크를 허락해요. 서버 IP 주소로 바로 열면
[Datasets 녹음](../bench-manager/datasets)이 마이크를 쓰지 못해요. SSH 터널로 연
`localhost` 주소는 괜찮아요. :::

## tmux로 오래 걸리는 일 돌리기

SSH 창을 닫으면 그 안에서 돌던 프로그램도 같이 꺼져요. 서버,
`make bench-batch`처럼 오래 걸리는 일은 tmux 안에서 돌려요.

<!-- S01-C001-07 S02-C001-10 -->

| 하고 싶은 것                                    | 명령                             |
| ----------------------------------------------- | -------------------------------- |
| 이름을 붙여 새 창 열기                          | `tmux new -s bench`              |
| 창에서 잠시 빠져나오기 (프로그램은 계속 돌아요) | `Ctrl+B`를 누르고 손을 뗀 뒤 `D` |
| 다시 들어가기                                   | `tmux attach -t bench`           |
| 열린 창 목록 보기                               | `tmux ls`                        |

창을 열고 바로 명령을 돌리려면 이렇게 해요. 로그는 `my_runs.log`에도 남아요.

<!-- S01-C001-07 -->

```bash
tmux new-session -d -s bench -c ~/STiTy "make bench-batch LIST=my_runs.txt 2>&1 | tee my_runs.log"
```

## 포트 한눈에 보기

| 포트    | 무엇                                                  |
| ------- | ----------------------------------------------------- |
| `29140` | 실험 매니저                                           |
| `29130` | 실험 매니저 API 서버. 웹사이트의 `/api` 요청을 받아요 |
| `8765`  | 대화 서버                                             |
| `8100`  | 대화 서버가 띄우는 번역 모델 서버                     |
